# Ideas 完整开发与案例验收

本计划保留并执行旧 `.structure` 的 T-001 至 T-005，并处理 README 中列出的演进欠账和公网发布必要项。基础工具版本固定为 Pi Development Harness 0.2.1。

## 必须完成

1. 旧根与模块 `.structure` 移走备份，业务 SQLite 数据单独一致性备份；重新初始化项目/模块身份。
2. 安装发布的 0.2.1 npm tarball，运行核心回归、项目原有测试和真实开发任务，记录可复现证据。
3. T-001：聊天代理支持 SSE，前端增量反馈与取消，异常可恢复，不以整段伪流式输出代替。
4. T-002：按动作配置模型路由，至少验证起名与追问选择不同模型；配置和密钥分离。
5. T-003：公网部署认证、会话、CSRF/请求边界与私密数据隔离；未认证私有 API 返回 401；提供明确的演示/登录体验。
6. T-004：同义实体可配置归并，覆盖每一步/每步、大模型/LLM，保留可解释证据。
7. T-005：可验证的增量图谱更新，结果与全量一致；代表性数百篇语料新增一篇时耗时小于全量重建的 30%，否则不得宣称完成。
8. 降低高频功能词噪声，提供语料驱动的处理与可见的配置边界；支持可选 OpenAI 兼容嵌入服务增强语义召回，默认不依赖外部服务。
9. 增量同步与冲突处理，覆盖新增、更新、删除和保存期间再次编辑，不能静默丢失用户修改。
10. 浏览器验收：桌面/移动布局、首次使用、念头到想法、追问/分叉/归档、图谱、导入导出、登录、离线与错误恢复。
11. 在 ten 建立独立服务、Nginx、HTTPS、持久数据目录、部署及回滚脚本；验证 ideas.cafedaily.top 的真实运行。
12. 创建 cafedaily/ides 公开仓库，排除私密数据，发布版本，并在 pi-development-harness 中建立案例链接与结构化验收记录。

## 证据要求

单元/集成/跨语言/浏览器检查需要真实执行。对模型的网络协议测试可使用明确标注的本地模拟端点；开发 Agent 的实际调用必须单独记录，不能用脚本 provider 伪装真实模型开发。性能结论需有基线、语料大小和可复现命令。任何不满足项保留为未完成。
