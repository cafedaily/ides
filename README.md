# 养想法

在线访问：[ideas.cafedaily.top](https://ideas.cafedaily.top)。

基于 Pi Development Harness 0.2.1 实际开发验证的项目案例。公开演示与私有空间隔离，支持流式追问、版本冲突处理、增量图谱和可选语义召回。

开发内核：[pi-development-harness](https://github.com/cafedaily/pi-development-harness)。验证记录见 [docs/harness-0.2.1-validation.json](docs/harness-0.2.1-validation.json)，部署与回滚见 [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)。

一个人的想法空间。念头进来，被追着问，慢慢长出形状；长不出来的，留下一句「为什么」。

这个仓库比之前那个单页多了一件事：**后端会把所有想法拆成关键词，建成一张图，
再把不同维度上的东西串起来。**

一条闭环：

```
念头 → 养起来（起名 + 第一问）→ 被追问 / 换角度 / 碰一下 / 分叉
     → 后端抽词建图 → 桥和路径告诉你「这个想法其实在说另一个想法的事」
     → 顺着那条线回去接着答
```

## 跑起来

只要 Python 3.9+。**没有必需的第三方依赖。**

```bash
make demo          # 建库 + 灌一份演示语料 + 建图
make serve         # http://localhost:8730
```

或者手动：

```bash
python3 -m yang init
python3 -m yang import 你导出的.jsonl.txt
python3 -m yang graph
python3 -m yang serve
```

想读加密导出的话再装一个（只有这一件事需要它）：

```bash
pip install cryptography
```

## 关键词图谱

### 维度

一个想法不是一坨文本，它是**几段各有身份的文本**：

| 维度 | 来自 |
|---|---|
| `title` | 标题 |
| `seed` | 最初那句 |
| `now` | 现在它是什么 |
| `ask` `angle` `collide` `note` | 生长记录，按动作分 |
| `why` | 凉了的想法：为什么凉了 |
| `spark` | 还没成形的念头 |

同一个词出现在不同维度上，是整个图谱的立足点。

### 从文本到词条（`yang/text.py`）

中文没有空格。这里不用词典，用**滑动二元组 + 长度提升**：

- 标点断开，二元组不跨句子；
- 两个字都是功能词的组合直接丢（`的了` `就是` `因为`）；
- 三字/四字串如果出现次数接近它内部二元组的次数，就把长的留下、把短的扣掉
  ——「下雨」和「雨天」这样被合成「下雨天」。

为什么不用定长切块：切块要选切点，而**切点不对齐，两句话共同的部分就消失了**。
`给每一步加` 和 `每步只学` 用定长切块永远对不上；滑动二元组能对上。代价是噪声多，
所以后面靠停用表和 TF-IDF 压。

还有两条规则专门对付**跨了词边界**的二元组：

- `数词/指示词 + 量词 + X` 里的「量词X」扔掉——`一个|想法` `一间|只在` `那家|店的`
  `四个|人轮流`。量词字有一半同时是常见的名词（门、家、条、本、部、场），
  所以不能无条件扔量词开头的二元组，**左邻的数词才是「这里是量词」的证据**。
- 虚词开头/结尾的扔掉（`的人` `做不` `跑得`），两个字都是功能词的扔掉。

### 实体归并（`yang/entity.py`）

上面那一层是**逐段**看文本的，它只能发现在同一段里重复出现的多字词
（`下雨天` 说了三次才长得出来）。可大部分实体在每篇里只说一次：
「一个定期见面的理由」在两篇里各出现一次，逐段的眼光永远看不见它，于是它被
打碎成 `个定` `定期` `期见` `见面` 四条。

碎成四条不只是难看，它有三处实际后果：

1. **余弦被灌水**：两篇共有的其实是一个实体，点积里却算了四次，于是
   「共有一个长短语」的两篇排在了「共有四个不同概念」的两篇前面；
2. **桥的名额被占**：`PER_PAIR=2` 本来是给一对想法留两条不同线索的，结果两条
   都是同一个短语的碎片；
3. **界面上那行「共有词」没法读**：`间只 天开 天它 家店` 没有一个是词。

所以在抽词之前先扫一遍全语料，把总是一起出现的一串字认成一个实体，
交回给分词层优先整体匹配。一个候选串要过三关：

| | |
|---|---|
| **出现够多** | 跨语料至少两次。只说过一次的短语连不上任何东西 |
| **边界干净** | 头上不能是数词/指示词/量词/介词/副词，尾巴上不能是虚词/介词/方位词 |
| **凝固** | 它出现的次数要接近它内部每个二元组各自出现的次数——那些二元组基本只因为它才存在 |

边界那关有一处刻意的不对称：**量词只砍头，不砍尾，而且只在左边确实站着一个
数词的时候砍**。`一个定期见面` 的 `个` 该砍，`下雨天开门` 的 `门` 不能砍。
左邻的字可能落在候选窗口外面（`一个定期见面的理由` 有九个字），所以左邻从语料里
查——这是整个模块唯一一处邻接统计，它撑得住是因为要回答的问题是二元的
（左边是不是数词），不是去估一个熵。

在演示语料上（12 篇）认出来六条，没有一条是垃圾：

```
定期见面的理由  下雨天开门的店  下雨天开门  值夜班的人  复印店  下雨天
```

i-cook 和 c-social 的共有词从 `理由 个定 定期 期见 见面` 五条变成
`定期见面的理由` 一条，这条桥也从榜上第九升到第六。

**不用邻接熵**：无监督分词的标准做法是左右邻接熵（真词的上下文丰富，碎片的
上下文单一），这里不用，因为它在这个规模上估不准——一个人的想法空间只有几十篇，
一个短语出现两三次，算出来的熵是噪声不是信号。凝固度只要两个计数，在小语料上
退化得体面得多。等语料涨到几百篇再换。

**代价**：实体是语料的属性，不是单篇的属性，所以**加一篇想法可能改变旧想法的
词条**。这是有意的，代价是图谱不增量，`rebuild` 每次从头算。几十篇没问题。

### 权重（`yang/terms.py`）

TF-IDF，一个想法算一篇。维度带权（标题 1.7、现在它是什么 1.35、随手记 0.9），
因为标题和「现在它是什么」是他反复改过的，比一次性的回答更能代表这个想法。
语料只有几十篇，IDF 必须平滑，不然只出现一次的词会被吹上天。每篇留权重最高的 24 个。

### 图上有什么（`yang/graph.py`）

- **想法—词条** 二部图，边权是这个词在这篇里的权重，边上带「出现在哪几个维度」；
- **词条共现**：NPMI，两个词一起出现是不是超出了各自都很常见能解释的程度；
- **想法相似**：词向量余弦，每个想法最多留 6 条，免得图糊成一坨；
- **桥**：同一个词把两个想法串起来，而且**串的是不同的维度**。

桥的打分：

```
score = w_A(词) × w_B(词) × 维度加成
维度加成 = 1.0   两边维度一样
         = 1.35  跨维度
         = 1.7   一头在「为什么凉了」
```

这个加成是**启发式，不是原理**。写在这儿是为了能被质疑和调。之所以给
「为什么凉了」最高分：一个已经死过一次的教训，正好长在一个还活着的想法身上——
这是这张图能给出的最有用的一种连接。

每条桥都带两边的**原话**，点得回去。抽象的连接没有用，能读到那一句才有用。

- **路径**：两个想法一个共同词都没有的时候，在二部图上跑 Dijkstra（边代价 = 1/权重），
  走出 `想法 → 词 → 想法 → 词 → 想法` 的链子。中间每一跳都是真实出现过的词。
  找不到就说找不到，不编。

## 接口

全部在 `127.0.0.1` 上，没有认证——它假设只有你自己用。要开到别的地址必须显式
`--host`，而且它会当着你的面说清楚这意味着什么。

| | |
|---|---|
| `GET /api/health` | 活着吗，有多少东西 |
| `GET /api/state` | 全量读 |
| `POST /api/state?mode=merge\|replace` | 全量写（先校验，不过就 422） |
| `GET /api/graph` | 节点、边、共现、相似、桥 |
| `GET /api/bridges?limit=` | 只要桥 |
| `GET /api/related?id=` | 和这个想法有关的 |
| `GET /api/path?a=&b=` | 串一串 |
| `GET /api/search?q=` | 按词找想法 |
| `GET /api/export?pass=` | 导出 jsonl |
| `POST /api/import?apply=1&mode=` | 导入（不带 apply 就是只验） |
| `POST /api/rebuild` | 重建词表缓存 |
| `POST /api/chat` | 转发到配好的 OpenAI 兼容模型（追问、换角度等） |

## 两处必须一起改的地方

导出格式有两份实现，Python 一份、JS 一份。**两边算出来的指纹不一样，
是最难查的一类 bug**，所以：

| 改这个 | 就必须同时改 | 而且要跑 |
|---|---|---|
| `yang/jsonl.py` | `web/src/yangdata.js` | `tests/test_jsonl.py` 里的跨语言对照 |

那两条测试会真的起一个 node，让两边互读对方写的文件。**没装 node 的时候它们报
「跳过」（`⊘`），不是「通过」**——没跑过的东西不算验证过，绿勾会骗人。

## 数据

`yang.db`，一个 SQLite 文件，拷走就是全部。前端在浏览器里还留着一份
IndexedDB，后端在就往上同步，后端不在就完全本地跑——**任何一边挂掉，
应用都还能用**。

导出格式 `yang.jsonl` v3：一行一条记录，首行文件头，每行一条加盐指纹，
整份一条加盐指纹，可选 AES-GCM-256 口令加密。细节见 `yang/jsonl.py` 顶部。

## 前端和后端怎么配合

公开 `/api/health` 只用于识别服务。浏览器必须通过 `/api/session` 验证登录后，才能读取私有状态。演示与私有空间使用不同的 localStorage / IndexedDB 名称；退出登录会清除页面中的私有内容，未同步草稿留在私有命名空间，下一次登录后恢复。

`save()` 防抖 600ms，以记录为单位提交变更；请求期间发生的新编辑进入下一次提交。前端保存上一次确认的基线，遇到 409 后做三方比较，无冲突记录自动合并，冲突记录让用户明确选择。网络错误保留草稿，可重试同步和导出本机副本。

追问、换角度、碰一下和分叉通过私有 `/api/chat` 调用配置的 OpenAI 兼容服务。`conf.route` 按动作选择模型。服务不可用时可使用内置题库；向量候选与词条证据分别解释。

## 实现边界

- 同义词归并依赖明确的规则和可配置词表，不声称覆盖所有自然语言改写。
- 词条质量仍包含中文启发式规则；自定义忽略词和语料频率抑制可调整，但不保证语义正确。
- 增量图谱缓存保存在单个服务进程内，重启后第一次查询全量构建；全局 IDF 会精确重算，图谱规模很大时仍有文档对计算成本。
- 语义服务默认关闭，启用后由所选服务商处理文本；网络协议测试使用模拟端点，具体模型的检索质量需在自己的语料上评估。
- 当前身份模型是单个拥有者的共享访问口令；浏览器退出清除本机 cookie，轮换口令可撤销所有会话。未实现多人账号体系。

## 当前实现与验证

- 私有 API 认证；模型密钥只保存在服务端，浏览器仅暂存新输入。明文导出不含密钥。
- `/api/sync` 使用 `base_revision` 和每集合的 `upsert/delete`。409 冲突不会写库；浏览器保留本机草稿，合并无冲突项，冲突项由用户选择。
- 真正转发上游 SSE，支持增量显示和取消。语义召回默认关闭，需要手动启用并选择 `/embeddings` 模型；候选单独标注向量相似度与共同词条。
- 图谱维护每篇文档统计、全局实体和 IDF、共现及文档对缓存。新进程从全量初始化，缓存最多保存四个数据库。设置变更使缓存失效；全量参考与增量结果逐项一致。
- 自定义同义词、每一步/每步、LLM/大模型归并和基于语料的功能词抑制都保留原文证据。

```bash
python -m pip install cryptography
python tests/run.py
python scripts/check_web.py
python web/build.py --output dist/index.html
python scripts/benchmark_graph.py
npm install --no-save playwright
npx playwright install chromium
node tests/browser.mjs
```

浏览器测试启动独立的临时数据库和明确标注的模拟模型服务，验证真实 UI、HTTP 和 SSE 协议。它不读取个人数据库或模型密钥；真实 Agent 的开发调用另外记录，不能把协议模拟当作真实模型效果验收。

公共演示仅在浏览器存储数据，支持本地圈图；词条证据桥、路径和模型调用在登录私有空间后使用。旧版 `yang.v1` / `yang` 浏览器数据不会被自动合入新空间，需由用户导出后显式导入。API 图谱性能基准不包含 HTTP 序列化时间，原始计时见 `docs/graph-benchmark.json`。
