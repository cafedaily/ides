## Current truths

- /api/chat backend model selection reads conf.models and optional conf.route[action].
- When body.action maps to a configured model id, yang/chat.py sends the OpenAI-compatible request to that model's base URL and model name.
- Missing action, missing route, empty route value, or an unrouted action remains compatible by selecting the first configured model.
- If conf.route[action] names a model id not present in conf.models, complete returns ok:false with an error naming the action and missing id before any outbound request.

## Don't assume

- Model API keys must not be printed or exposed to the frontend.
- Configured model routes are validated at request time, not during data-entry rendering.
