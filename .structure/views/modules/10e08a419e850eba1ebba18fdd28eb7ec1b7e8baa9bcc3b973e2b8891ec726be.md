## Current truths

- Authentication helpers live in yang/auth.py and are stdlib-only: env policy loading, weak token detection, bearer validation, HMAC signed expiring session cookies, origin matching, and bounded login throttling.
- In production/non-loopback startup, YANG_AUTH_TOKEN must be a strong token; loopback development without a token remains compatible, and an explicit unsafe development flag allows non-loopback no-auth construction.
- The HTTP server enforces bearer or signed session-cookie authentication for private API routes when a token is configured or production mode is active. GET /api/health is publicly available and redacts counts for anonymous users; /api/session, /api/login, and /api/logout support frontend sessions.
- Cookie-authenticated mutations are checked against YANG_PUBLIC_ORIGIN; explicit bearer clients may mutate cross-origin. Session cookies are HttpOnly, SameSite=Strict, expiring, and Secure in production policy.
- GET /api/state redacts model keys and reports keyConfigured. State/config writes preserve existing model keys by model id when omitted or blank, and clear them only when clear_key=true. Plain exports do not leak model keys.
- The server validates Content-Length, caps JSON request bodies, uses finite socket timeouts, returns generic internal-error responses, and resolves static file paths under the configured web root.
